# Vercel Environment Variable Checklist

## Required Environment Variables for Production

### Database Configuration
- [ ] `MONGODB_URI` - MongoDB connection string (Production Atlas cluster)
  - **Source:** Secure secret management (Vercel Secrets)
  - **Example:** `mongodb+srv://username:password@cluster.mongodb.net/skytouchclean?retryWrites=true&w=majority`
  - **Check:** Verify connection string points to production cluster, not development
  - **Security:** Never commit to git, use Vercel dashboard or CLI

- [ ] `MONGODB_DB` - Database name
  - **Value:** `skytouchclean`
  - **Environment:** Production

### Authentication & Security
- [ ] `SESSION_SECRET` - Secret key for session encryption
  - **Source:** Generate secure random string (32+ characters)
  - **Command:** `openssl rand -base64 32`
  - **Check:** Ensure it's different from development
  - **Security:** Rotate periodically

### Paystack Payment Configuration
- [ ] `PAYSTACK_SECRET_KEY` - Paystack secret key (LIVE mode)
  - **Source:** Paystack Dashboard → Settings → API Keys
  - **Check:** Must start with `sk_live_` (not `sk_test_`)
  - **Security:** Never expose to client-side code
  - **Verification:** Test with small live transaction before going live

- [ ] `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` - Paystack public key (LIVE mode)
  - **Source:** Paystack Dashboard → Settings → API Keys
  - **Check:** Must start with `pk_live_` (not `pk_test_`)
  - **Note:** Safe to expose to client-side (public)

- [ ] `NEXT_PUBLIC_SITE_URL` - Production site URL
  - **Value:** Your production domain (e.g., `https://skytouchclean.com`)
  - **Check:** Must use HTTPS
  - **Purpose:** Used for Paystack callback URLs

### Email Configuration (if using email provider)
- [ ] `EMAIL_PROVIDER` - Email provider name
  - **Options:** `resend` (default) or `sendgrid`
  - **Environment:** Production

- [ ] `RESEND_API_KEY` - Resend API key (if using Resend)
  - **Source:** Resend Dashboard → API Keys
  - **Security:** Server-side only
  - **Check:** Verify it's a production key

- [ ] `SENDGRID_API_KEY` - SendGrid API key (if using SendGrid)
  - **Source:** SendGrid Dashboard → API Keys
  - **Security:** Server-side only
  - **Check:** Verify it's a production key

- [ ] `SENDGRID_FROM_EMAIL` - Sender email (if using SendGrid)
  - **Value:** Verified sender email in SendGrid
  - **Check:** Must be verified in SendGrid dashboard

### Admin Account
- [ ] `ADMIN_EMAIL` - Admin account email
  - **Value:** Production admin email
  - **Check:** Should be different from development

- [ ] `ADMIN_PASSWORD` - Admin account password
  - **Source:** Secure password generator
  - **Requirements:** Minimum 12 characters, mixed case, numbers, symbols
  - **Security:** Force password change on first login
  - **Action:** Change immediately after first login

- [ ] `ADMIN_NAME` - Admin account name
  - **Value:** Admin full name

## Environment-Specific Configuration

### Production Environment (Vercel Production)
All variables above must be set with production values.

### Preview Environments (Vercel Preview Branches)
- [ ] `MONGODB_URI` - Use production database (recommended) or separate preview database
- [ ] `PAYSTACK_SECRET_KEY` - Use test keys (`sk_test_`) for preview deployments
- [ ] `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` - Use test keys (`pk_test_`) for preview deployments
- [ ] `NEXT_PUBLIC_SITE_URL` - Use preview deployment URL (auto-generated by Vercel)
- [ ] `SESSION_SECRET` - Can use same as production or separate
- [ ] Email configuration - Use same as production (safe) or disable for previews

## Pre-Launch Verification Steps

### 1. Database Verification
- [ ] Test MongoDB connection from production environment
- [ ] Run `npm run setup-indexes` on production database
- [ ] Run `npm run seed` on production database
- [ ] Verify all services and prices are loaded correctly
- [ ] Verify indexes are created (check `payments.reference` unique index)

### 2. Paystack Verification
- [ ] Configure webhook URL in Paystack dashboard: `https://yourdomain.com/api/payments/webhook`
- [ ] Test successful payment flow with live keys (small amount)
- [ ] Verify webhook signature validation works
- [ ] Verify callback URL redirects correctly
- [ ] Check transaction appears in Paystack dashboard
- [ ] Verify payment is marked PAID in database
- [ ] Test failed payment scenario
- [ ] Test abandoned payment scenario

### 3. Email Verification (if enabled)
- [ ] Send test email to verify provider works
- [ ] Check email arrives in inbox (not spam)
- [ ] Verify email content renders correctly
- [ ] Test OTP code generation and verification

### 4. Admin Access Verification
- [ ] Login with admin credentials
- [ ] Verify session cookie is httpOnly
- [ ] Verify session works across page loads
- [ ] Test logout functionality
- [ ] Verify protected routes redirect to login
- [ ] Change admin password after first login

### 5. Security Verification
- [ ] Verify all API routes use Node.js runtime where needed
- [ ] Check that sensitive variables are not exposed to client
- [ ] Verify rate limiting is working
- [ ] Test authentication on protected routes
- [ ] Verify CORS settings (if applicable)

### 6. Functionality Verification
- [ ] Test all three booking flows (cleaning, laundry, fumigation)
- [ ] Verify unique references are generated
- [ ] Test pricing calculations
- [ ] Verify OTP verification works
- [ ] Test payment initialization flow
- [ ] Verify status lookup with OTP

## Rollback Plan

### If Critical Issues Found
1. Revert to previous deployment in Vercel
2. Switch Paystack back to test mode if payment issues
3. Restore database from backup if data corruption
4. Disable email provider if email issues
5. Rotate session secret if security breach
